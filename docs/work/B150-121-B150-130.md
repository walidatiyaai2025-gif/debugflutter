# B150-121..130 — SQLite Persistence & Profiles

Status: IN PROGRESS — implementation committed, CI validation pending

## Implemented scope

- B150-121: SQLite bootstrap plus explicit `schema_info` version table and idempotent initialization.
- B150-122: repository/workspace history schema and upsert contract.
- B150-123: sanitized command execution history schema.
- B150-124: diagnostics summary history schema (counts/summary only; no raw logs).
- B150-125: repair history schema with recipe/signature/risk/status/verified fields.
- B150-126: build history schema with artifact type/mode/status/timing/path/size/hash.
- B150-127: release receipt history schema with artifact metadata/hash.
- B150-128: application setting key/value persistence.
- B150-129: per-repository preferred JDK/device/build-profile persistence.
- B150-130: schema initialization/newer-version rejection and retention regression tests.

## Storage and safety

- Runtime database path: `%LOCALAPPDATA%/FlutterBuildDoctor/flutter-build-doctor.db`.
- SQL is parameterized; table names used by retention are internal constants, not user input.
- Schema stores sanitized command text and compact diagnostic summaries, not raw command output.
- Release/build history stores artifact metadata and SHA-256, never signing password/key material.
- Unknown newer schema versions are rejected instead of silently downgraded.
- Retention is bounded by maximum age and maximum row count per history table.

## Dependency

Uses `Microsoft.Data.Sqlite` as the lightweight ADO.NET SQLite provider. The package is isolated to the Infrastructure project.

## Validation gate

Release build and full tests must pass before this stacked slice is considered verified.
