# FBD-309 — Implement safe refresh/reclone workflow

## Status

DONE

## Scope

Safely recreate an existing Git repository without silently overwriting local work. The workflow must preserve the original repository as a backup, validate both the replacement and final promoted repository, and restore the original automatically when a risky swap fails.

## Integration review

FBD-309 builds on the existing merged Git Repository Manager rather than reimplementing earlier tasks:

- FBD-303 `IGitCloneService` performs the staging clone and retains URL validation, non-interactive Git execution, progress, cancellation, timeout, and target-directory protections.
- FBD-307 `IGitWorkingTreeScanner` performs the read-only preflight and captures whether the original repository is dirty before any mutation.
- FBD-308 `IGitRepositoryIdentityService` verifies the original repository, the staging clone, and the promoted final repository without exposing credential-bearing remote URLs.
- The WPF runtime composition registers the workflow and all of its dependencies for later consumption by FBD-310.

No earlier Git operation was rewritten.

## Implementation

Added:

- `GitRepositoryRefreshContracts.cs`
  - typed request/result/status contracts
  - backup, staging, failed-replacement and rollback metadata
  - preservation of component scan/clone/identity results
- `GitRefreshFileSystem.cs`
  - narrow filesystem boundary for move/delete operations and deterministic rollback testing
- `GitRepositoryRefreshService.cs`
  - validates existing Git repository
  - scans dirty state before mutation
  - verifies original identity
  - clones to a unique sibling staging directory
  - verifies staging identity before touching the original
  - moves the original repository to a unique backup path
  - promotes staging to the original path
  - verifies final Git identity
  - restores backup automatically if promotion fails
  - quarantines an unverified promoted replacement and restores backup if final verification fails
  - preserves the backup after success, including uncommitted local work
  - performs only best-effort cleanup of generated staging directories; it never deletes the original repository

## Safety properties

- Clone/preflight failure leaves the existing repository untouched.
- Dirty repositories are not treated as disposable; the entire original directory is retained in the backup.
- The original directory is moved, not deleted.
- A replacement is verified before and after promotion.
- Promotion failure triggers automatic restoration from backup.
- Final verification failure quarantines the replacement under `*.fbd-failed-*` and restores the backup.
- A rollback failure is reported explicitly and returns the backup location instead of claiming success.
- Existing cancellation/timeout semantics from the underlying Git services are preserved.
