# B150-101..110 — Repair Engine Core

Status: IN PROGRESS — implementation committed, CI validation pending

## Implemented scope

- B150-101: stable SHA-256 issue signature from normalized code/category/evidence.
- B150-102: Safe/Risky/Destructive classification plus destructive/backup/confirmation assessment.
- B150-103: repair preview contract lists actions, affected paths, consequences, risk and verification steps.
- B150-104: file/directory restore-point backup service limited to selected project root.
- B150-105: explicit-confirmation rollback service restoring captured entries.
- B150-106: post-repair process verification contract/result.
- B150-107: `flutter clean` repair recipe.
- B150-108: dependency refresh / `flutter pub get` repair recipe.
- B150-109: ADB restart recipe (`kill-server`, `start-server`, `devices` verification).
- B150-110: stale project `build/` cleanup with project-child path guard and reparse-point refusal.

## Safety

- Repair actions are previewable before execution.
- Destructive actions require explicit confirmation even when classified as safe generated-output cleanup.
- Risky actions also require explicit confirmation.
- Rollback refuses to overwrite current files without explicit confirmation.
- Backup paths cannot escape the selected project root and reparse points are rejected.
- Stale-build cleanup resolves exactly `<project>/build`, refuses reparse points, and never deletes project root or siblings.
- ADB restart is marked Risky because it may interrupt active debug/device sessions.

## Validation gate

Release build and full tests must pass before the stacked PR is considered verified.
