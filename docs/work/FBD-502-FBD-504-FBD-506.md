# FBD-502 / FBD-503 / FBD-504 / FBD-506 — Flutter Doctor parsing and version probes

Status: IN PROGRESS — implementation committed, CI validation pending

## Scope

This slice establishes a typed, testable Flutter command-parsing layer without touching the active FBD-613 / `local.properties` scope.

## FBD-502 — Parse Flutter Doctor sections

- parses top-level marker sections from `flutter doctor -v`
- normalizes section status into Ready / Warning / Error / Unavailable / Unknown
- classifies known Flutter Doctor components
- keeps indented evidence attached to its parent section
- exposes ready/warning/error/unavailable/unknown summary counts

## FBD-503 — Preserve unknown Doctor output

- unknown future section headers are retained as `Unknown`
- raw output is preserved on the report
- raw lines are preserved per section
- non-section startup/noise lines are retained separately
- malformed/truncated output returns partial evidence rather than throwing

## FBD-504 — Structured `flutter --version` probe

- executes `flutter --version` using typed `ProcessRequest` arguments
- parses Flutter version and channel
- parses framework revision, engine revision/hash, Dart version and DevTools version when present
- preserves raw output
- maps failed/cancelled/timed-out process states explicitly
- does not report success when the primary version/channel header cannot be parsed

## FBD-501 prerequisite coverage

A typed `FlutterDoctorProbe` now executes `flutter doctor -v` through the existing `IProcessRunner`, applies the parser, preserves the execution result and supports cancellation/timeout behavior inherited from the process engine.

## FBD-506 — Fixture/regression coverage

Tests cover:

- success/warning/error/unavailable markers
- known component classification
- unknown future sections
- malformed/truncated output
- CRLF input
- structured Flutter/Dart/framework/engine/DevTools version parsing
- timeout mapping
- exact typed `doctor -v` and `--version` arguments
