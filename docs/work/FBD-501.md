# FBD-501 — Execute flutter doctor -v

Status: DONE pending final-head CI and merge

## Scope

Execute `flutter doctor -v` through the canonical `IProcessRunner` using the Flutter executable discovered by FBD-404. Preserve the complete `ProcessResult` so FBD-502 can parse raw stdout/stderr later. No doctor-section parsing, environment repair, SDK mutation, or package installation is introduced here.

## Implementation

- Added typed `FlutterDoctorExecutionRequest`, `FlutterDoctorExecutionResult`, `FlutterDoctorExecutionStatus`, and `IFlutterDoctorExecutor` contracts.
- Added `FlutterDoctorExecutor` with a five-minute default bounded timeout, cancellation propagation, explicit unavailable/invalid/failure/timeout/cancel statuses, and progress forwarding.
- Direct executables run with arguments `doctor -v`.
- Windows `.bat` / `.cmd` Flutter launchers run through `cmd.exe` while still using structured `ProcessRequest` arguments.
- Exact `ProcessResult` evidence is retained on terminal process outcomes, including stdout/stderr records, exit code, sanitized command, timing, status, and execution receipt.
- Registered `IFlutterDoctorExecutor` in production runtime-detection DI.

## Coverage

Unit tests cover unavailable Flutter, invalid timeout, pre-cancellation, direct executable command construction, Windows batch/cmd command construction, process terminal-status mapping, raw `ProcessResult` preservation, and runner cancellation.

Integration coverage uses a real Windows `ProcessRunner` against a temporary `flutter.cmd` shim and verifies both stdout and stderr are preserved, exit code/status are retained, and an execution receipt is produced. DI composition verifies singleton registration.
