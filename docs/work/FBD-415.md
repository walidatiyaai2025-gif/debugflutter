# FBD-415 — Detect Android license status

Status: DONE pending live-main PR CI and merge

## Scope

Detect Android SDK package license readiness from the FBD-408 effective sdkmanager without accepting licenses, installing packages, or modifying SDK/license files, and surface the result through the live Environment Doctor UI.

## Probe safety

- consumes the effective sdkmanager discovered by FBD-408
- runs a single bounded `--licenses` status probe through the canonical process runner
- invokes sdkmanager through `cmd.exe /d /v:off /s /c`
- forces standard input closed using `< NUL`
- never emits `y`, `yes`, `echo y`, or any acceptance input
- uses a 10-second timeout and preserves cancellation

## Evidence and classification

The detector preserves raw sdkmanager output, process result/receipt, command-line-tools revision, sdkmanager path, and names of local files under `<sdk>/licenses`.

Result states: `Accepted`, `Pending`, `SdkManagerUnavailable`, `ProbeFailed`, `TimedOut`, `Cancelled`, `Indeterminate`.

## Live UI integration

- `IAndroidLicenseDetector` registered as a production singleton
- Environment Doctor runs the status-only probe after command-line-tools and avdmanager discovery
- UI card displays Accepted/Ready, Action required, timeout/failure/indeterminate states, sdkmanager path, revision and local license-file evidence
- this task does not add an Accept button; explicit acceptance remains a later user-driven repair workflow

## Coverage

Backend unit tests cover accepted, pending/non-zero exit, pending-before-timeout, undecided timeout, failed probe, indeterminate output, cancellation, sdkmanager unavailable, local license evidence, and exact safe command construction.

Integration coverage validates the SDK-root -> command-line-tools -> license chain and asserts `< NUL` is present while `echo y` and `yes |` are absent.
