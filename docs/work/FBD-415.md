# FBD-415 — Detect Android license status

Status: DONE pending final-head CI and merge

## Scope

Detect Android SDK package license readiness from the FBD-408 effective sdkmanager without accepting licenses, installing packages, or modifying SDK/license files.

## Probe safety

- consumes the effective sdkmanager discovered by FBD-408
- runs a single bounded `--licenses` status probe through the canonical process runner
- invokes sdkmanager through `cmd.exe /d /v:off /s /c`
- forces standard input closed using `< NUL`
- never emits `y`, `yes`, `echo y`, or any acceptance input
- uses a 10-second timeout and preserves cancellation

## Evidence and classification

The detector preserves raw sdkmanager output, process result/receipt, command-line-tools revision, sdkmanager path, and names of local files under `<sdk>/licenses`.

Result states:

- `Accepted`
- `Pending`
- `SdkManagerUnavailable`
- `ProbeFailed`
- `TimedOut`
- `Cancelled`
- `Indeterminate`

Recognized accepted output includes `All SDK package licenses accepted`. Pending evidence includes known unaccepted-license text and interactive `Accept?` prompts. If a pending prompt is captured before timeout, the result is `Pending` and explicitly records that the bounded probe was stopped without providing input.

## Integration

- `IAndroidLicenseDetector` registered as a production singleton
- composes from FBD-407 SDK root through FBD-408 command-line-tools discovery
- FBD-908 remains the only later task responsible for an explicit user-driven license acceptance flow

## Coverage

Unit tests cover accepted, pending/non-zero exit, pending-before-timeout, undecided timeout, failed probe, indeterminate output, process cancellation, pre-cancellation, sdkmanager unavailable, license-file evidence, and exact safe command construction.

Integration coverage validates the FBD-407 -> FBD-408 -> FBD-415 chain with a deterministic runner and asserts `< NUL` is present while `echo y` and `yes |` are absent.
