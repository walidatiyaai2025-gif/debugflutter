# FBD-418 — Refresh environment action

Status: DONE

## Scope

Add an explicit Environment Doctor re-scan action that captures a new `EnvironmentSnapshot` and updates the existing dashboard without restarting the application. Keep all detector orchestration inside `IEnvironmentSnapshotService`; do not introduce repair behavior.

## Implementation

- Added `RefreshCommand` to the existing `EnvironmentDoctorViewModel`.
- Refresh requests a fresh `IEnvironmentSnapshotService.CaptureAsync` result and applies it to the existing component collection.
- The existing initial `InitializeAsync` remains idempotent; refresh is the only explicit re-scan path.
- The refresh command is disabled while a scan is already running, preventing concurrent environment captures from the UI.
- Successful refresh updates component state/path/version/action data plus capture timestamp and duration in place.
- Failed refresh preserves the last successful dashboard snapshot and surfaces a clear failure message instead of clearing known-good evidence.
- Added a `Refresh Environment` button to the Environment Doctor header.

## Safety boundaries

- No detector is called directly from the ViewModel.
- No PATH, JAVA_HOME, ANDROID_HOME, ANDROID_SDK_ROOT, SDK, JDK, Flutter, Git, Android Studio, license, or cache mutation.
- No repair action is introduced.
- No application restart or ViewModel recreation is required.

## Coverage

`EnvironmentDoctorViewModelTests` verifies:

1. Initial capture still maps the immutable snapshot to the full dashboard.
2. Repeated initialization remains idempotent without an explicit refresh.
3. Refresh performs a second capture and replaces Flutter path/version/timestamp evidence with the new snapshot.
4. Refresh failure preserves the last successful dashboard data and reports the failure.
5. Initial capture failure still does not claim a loaded environment.
