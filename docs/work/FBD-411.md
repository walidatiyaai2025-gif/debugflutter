# FBD-411 — Detect installed Android build-tools

Status: DONE pending final-head CI and merge

## Scope

Enumerate locally installed Android build-tools packages from the validated FBD-407 Android SDK root. This task is filesystem-only and performs no sdkmanager execution, package installation, SDK mutation, or environment changes.

## Discovery

- consumes the validated FBD-407 effective SDK root
- enumerates `<sdk>/build-tools/*`
- reads `Pkg.Revision` from `source.properties`
- falls back to a revision-looking directory name when metadata is missing
- treats metadata revision as authoritative when it differs from the directory name and preserves the mismatch in evidence
- records raw `source.properties`
- checks core tool readiness for `aapt2`, `zipalign`, `d8`, and `apksigner`

## Readiness semantics

A build-tools package is usable when a revision can be resolved and all four core tools are present. Partial/broken package directories remain visible and do not appear in `InstalledVersions`.

Result states:

- `Succeeded`
- `AndroidSdkRootUnavailable`
- `BuildToolsDirectoryMissing`
- `NoBuildToolsInstalled`
- `PartialInstallationsOnly`
- `InspectionFailed`

Usable installed versions are returned distinct and sorted descending.

## Integration

- `IAndroidBuildToolsDetector` registered as a production singleton
- composes directly from FBD-407 SDK-root detection
- no subprocess execution or mutation
- preserves the completed platform, cmdline-tools, and ADB detectors

## Coverage

Unit tests cover multiple complete versions and ordering, missing metadata with directory fallback, metadata/directory mismatch, partial package readiness, mixed usable/partial packages, missing/empty build-tools directories, and invalid SDK root handling.

Integration coverage validates FBD-403 environment snapshot -> FBD-407 SDK root -> FBD-411 build-tools inventory on a real temporary SDK layout.
