# FBD-607 — Parse Kotlin plugin version

Status: IN PROGRESS

## Goal

Detect an explicit Kotlin Gradle plugin version from the Gradle scripts already identified by FBD-604 without executing Gradle or guessing dynamic/version-catalog values.

## Implementation

- added `IKotlinPluginVersionParser` with typed status and declaration evidence
- supports modern `org.jetbrains.kotlin.*` plugin DSL declarations in Groovy and Kotlin DSL
- supports Kotlin DSL shorthand such as `kotlin("android") version "..."`
- supports direct legacy `org.jetbrains.kotlin:kotlin-gradle-plugin:<version>` classpath declarations
- supports legacy `kotlin_version` / `extra["kotlin_version"]` properties only when Kotlin Gradle plugin context is present
- ignores commented-out declarations
- preserves repeated identical-version evidence and returns `Ambiguous` when explicit versions conflict
- does not resolve variables, aliases, or version catalogs when no literal version is available
- revalidates every FBD-604 script path against the expected role/DSL location
- rejects reparse/symlink paths and scripts above the 512 KiB inspection limit
- registers the parser as a production singleton

## Safety boundary

FBD-607 performs bounded read-only Gradle script inspection only. It does not execute Gradle/gradlew, evaluate Groovy/Kotlin code, resolve version catalogs, download plugins, modify files, or expose raw Gradle script text.

## Coverage

Unit coverage includes modern Groovy/Kotlin declarations, Kotlin shorthand, legacy classpath, guarded legacy version properties, commented declarations, dynamic versions, repeated/conflicting versions, and raw-text contract protection. Boundary coverage validates role/path/reparse/size/stale-file handling. Composition coverage verifies production singleton registration.
