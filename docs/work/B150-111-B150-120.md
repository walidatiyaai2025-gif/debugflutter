# B150-111..120 — Release Center Core

Status: IN PROGRESS — implementation committed, CI validation pending

## Implemented scope

- B150-111: release preflight aggregates package ID, version, signing and manifest checks.
- B150-112: signing readiness checks presence of required settings/keystore without returning password/key values.
- B150-113: application/package ID extraction and structural validation.
- B150-114: `pubspec.yaml` versionName + positive versionCode validation.
- B150-115: main manifest checks for application, MAIN/LAUNCHER entry and explicit debuggable=true.
- B150-116: release artifact receipt carries type/path/size/SHA-256 from the verified build receipt.
- B150-117: safe Windows Explorer output-directory and reveal-artifact action contract using typed paths.
- B150-118: bounded in-memory release history model/store (persistent store is a later persistence slice).
- B150-119: Release APK preflight → build → artifact receipt → history orchestration.
- B150-120: Release AAB preflight → build → artifact receipt → history orchestration.

## Safety

- Release builds do not start while preflight has blockers.
- Signing inspector never places storePassword, keyPassword, keyAlias value, or storeFile value in report evidence; only setting names/readiness are surfaced.
- Keystore path is used internally only to check file existence.
- Output actions require an existing artifact and use typed explorer arguments.
- Release success requires the underlying build receipt to contain a verified hashed artifact.

## Validation gate

Release build and full tests must pass before the stacked PR is considered verified.
