# FBD-308 — Display current commit/branch/remote

## Status

DONE

## Scope

Expose the exact Git identity for the selected repository in the WPF project header without mutating the repository or exposing remote URLs that may contain credentials.

## Implementation

- Added typed repository-identity contracts under `FlutterBuildDoctor.Git.Repository`.
- Added read-only `GitRepositoryIdentityService` backed by the canonical `IProcessRunner`.
- Reads the current branch with `git branch --show-current`.
- Reads the exact current commit with `git rev-parse --verify HEAD`.
- Reads the configured upstream with `git rev-parse --abbrev-ref --symbolic-full-name @{upstream}` when available.
- Reads the branch remote name with `git config --get branch.<branch>.remote` when available.
- Deliberately does not call `git remote get-url` and does not expose remote URLs because URLs may contain embedded credentials.
- Supports detached HEAD as a valid identity state.
- Treats ordinary missing-upstream/missing-remote metadata as optional rather than failing an otherwise valid branch/commit identity.
- Preserves timeout/cancellation and non-interactive Git/GCM behavior.
- Added `ProjectHeaderViewModel` for reusable presentation of repository identity.
- `ProjectHeaderViewModel.LoadAsync(...)` keeps property updates on the caller/UI synchronization context.
- Added full commit SHA, branch, remote/upstream and repository-path presentation to the MainWindow header.
- Added the Git project reference to the WPF app and registered the identity service/header ViewModel through DI.
- Updated shell composition so `MainWindowViewModel` exposes the project-header ViewModel for binding.

## Security

- Remote URL retrieval was intentionally removed before validation.
- The header shows only remote name and upstream ref, which satisfy the task acceptance criteria without risking disclosure of embedded Git credentials.
- Existing secret-redaction and non-interactive process rules remain unchanged.
