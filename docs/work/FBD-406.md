# FBD-406 — Detect Java installations

## Status

DONE

## Scope

Discover the effective Java installations visible through Windows PATH, preserve PATH-order conflicts, and expose version/vendor/architecture/JDK metadata without modifying PATH or JAVA_HOME.

## Integration review

- Reuses FBD-402 `IPathExecutableDiscovery`; no second PATH search implementation was introduced.
- Reuses the canonical `IProcessRunner` for bounded, cancellable metadata probes.
- Registers `IJavaInstallationDetector` through the existing runtime-detection DI composition.
- Adds the Android project reference to the WPF host without changing the completed Git Repository Manager or FBD-404 Flutter detector behavior.
- FBD-403 remains responsible for environment-variable capture; FBD-406 does not read or mutate global JAVA_HOME/PATH as an authoritative source.
- Compatibility-based Java selection remains FBD-708; a broken preferred PATH Java is not silently replaced by a shadowed candidate.

## Implementation

- Added typed Java detection contracts in `FlutterBuildDoctor.Android.Detection`.
- Enumerates every effective `java.exe` match returned by FBD-402.
- Probes each candidate with `java -XshowSettings:properties -version`.
- Captures `java.version`, `java.vendor`, `os.arch`, and `java.home` from Java property output.
- Falls back to the standard `java/openjdk version "..."` banner when `java.version` is unavailable.
- Detects JDK readiness through `javac.exe` under the discovered Java home.
- Handles the legacy `<jdk>/jre` layout by checking the parent JDK for `bin/javac.exe`.
- Preserves preferred/shadowed PATH ordering and complete candidate evidence.
- Maps missing Java, probe failure, timeout, and cancellation to explicit typed states.
- Does not mutate machine/user/process PATH or JAVA_HOME.
