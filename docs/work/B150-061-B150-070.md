## Design boundary

Compatibility policy data is intentionally supplied as `CompatibilityRequirements` rather than hardcoded into the engine. Tool-version support matrices change over time; detectors/project analyzers can provide the requirement evidence while this domain engine performs deterministic, testable evaluation.

The engine is read-only. It does not install SDKs, change Gradle files, mutate PATH/environment variables, accept licenses, or perform repairs.

## Tests
