# FBD-608 — Parse compileSdk / minSdk / targetSdk

Status: IN PROGRESS

## Goal

Extract Android SDK requirement evidence from the exact FBD-604 app Gradle script without executing Gradle or guessing arbitrary dynamic expressions.

## Implementation

- added `IAndroidSdkRequirementsParser` with typed status, per-field values, evidence, and unresolved-field reporting
- supports Groovy and Kotlin DSL literal `compileSdk`, `minSdk`, and `targetSdk` forms, including legacy `*SdkVersion` spellings
- preserves the common Flutter-managed references `flutter.compileSdkVersion`, `flutter.minSdkVersion`, and `flutter.targetSdkVersion` as typed references instead of inventing numeric API levels
- returns partial/unresolved evidence for unsupported dynamic expressions and `Ambiguous` for conflicting explicit values
- revalidates the exact FBD-604 app script path and rejects stale, reparse/symlink, or oversized script evidence
- ignores comments and string literals and exposes no raw Gradle source text
- scopes `compileSdk` matching to `android { ... }` blocks and `minSdk` / `targetSdk` matching to nested `defaultConfig { ... }` blocks, preventing helper variables or lookalike declarations elsewhere in the file from becoming false SDK requirements
- rejects unreasonable numeric API values rather than accepting accidental large integers
- registered the parser as a production singleton

## Safety boundary

FBD-608 performs bounded read-only static Gradle inspection only. It does not execute Gradle/gradlew, evaluate Groovy/Kotlin expressions, resolve version catalogs, modify files, or infer values from unrelated scripts.

## Coverage

Unit coverage includes Groovy/Kotlin literals, Flutter references, mixed literal/reference values, unresolved dynamics, conflicts, comments/strings, missing app script, no-raw-source contract, Android/defaultConfig scope regression tests, and unreasonable API values. Boundary coverage validates path/reparse/size/stale-file behavior. Composition coverage verifies DI registration.
