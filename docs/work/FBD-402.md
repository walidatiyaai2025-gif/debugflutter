# FBD-402 — Implement PATH executable discovery utility

## Status

DONE

## Scope

Provide a reusable Windows executable discovery utility that resolves every matching executable from the effective PATH/PATHEXT ordering and exposes preferred/shadowed matches for later Flutter, Java and Android tool detection.

## Architecture

- Contracts live in `FlutterBuildDoctor.Application.Environment` so Flutter/Android/Infrastructure consumers can share the result model without depending on WPF.
- Windows filesystem resolution lives in `FlutterBuildDoctor.Infrastructure.Environment`.
- Discovery is filesystem-only; it does not invoke `where.exe`, a shell, or any subprocess.
- Production DI registers `IPathExecutableDiscovery` as a singleton.

## Implementation

Added `PathExecutableDiscoveryContracts.cs` with:

- `PathExecutableDiscoveryRequest`
- `PathExecutableDiscoveryResult`
- `PathExecutableMatch`
- `IgnoredPathEntry`
- `IPathExecutableDiscovery`
- explicit success/invalid-request status
- preferred-match and conflict helpers

Added `WindowsPathExecutableDiscovery` with:

- PATH-order preservation
- PATHEXT-order preservation inside each PATH directory
- all matching executables returned, not only the first one
- first match marked preferred and later matches marked shadowed
- case-insensitive deduplication of PATH directories while preserving first occurrence/index
- case-insensitive deduplication of resolved executable paths
- quoted PATH entry handling
- environment-variable expansion
- explicit-extension exact-file lookup
- default PATHEXT fallback `.COM;.EXE;.BAT;.CMD`
- empty PATH segments ignored so current-directory executable lookup is not enabled implicitly
- invalid executable names containing traversal, drive or directory syntax rejected
- Windows drive roots such as `C:\` preserved instead of being normalized incorrectly to `C:`

## Integration review

FBD-402 does not replace the existing FBD-301 Git detector. It introduces a generic path-discovery primitive for subsequent environment tasks. FBD-404 Flutter detection, FBD-406 Java detection and later Android executable detection can now consume one consistent Windows resolution model and surface conflicts instead of silently taking whichever executable happens to launch first.

No global PATH/PATHEXT values are mutated.
