# FBD-310 — Repository Manager UI

## Status

DONE

## Scope

Provide a usable WPF repository import workflow where the user supplies a Git URL, branch and workspace, while composing the already-merged Git Repository Manager services rather than issuing new raw Git commands from presentation code.

## Integration review

FBD-310 composes the existing Git stack:

- FBD-301 Git detection resolves the actual Git executable path/version.
- FBD-303 `IGitCloneService` handles new clones and URL/target validation.
- FBD-304 `IGitBranchService` refreshes/enumerates local and remote branches.
- FBD-305 `IGitBranchSwitcher` performs safe local/remote branch switching.
- FBD-308 `ProjectHeaderViewModel` reloads exact branch/commit/remote identity after a successful import.
- FBD-309 `IGitRepositoryRefreshService` safely refreshes an existing Git target through backup/staging/rollback semantics.

No raw Git process construction was added to the WPF ViewModel.

## Implementation

Added:

- `GitExecutableResolver`
  - resolves the registered FBD-301 Git detector from `IToolDetector`
  - returns path/version/readiness without hardcoding `git.exe`
- `RepositoryImportCoordinator`
  - starts through `IGitCloneService`
  - if clone reports an existing non-empty target, it only proceeds when that target is already Git metadata-backed
  - existing Git targets are routed through FBD-309 safe refresh
  - non-Git occupied folders are rejected without deletion or overwrite
  - refreshes branch inventory
  - prefers an exact local branch over an equivalent remote branch
  - supports explicit remote-qualified branch input
  - switches branches through FBD-305 when needed
  - preserves backup path/result metadata from safe refresh
- `RepositoryManagerViewModel`
  - Git URL, branch and workspace fields
  - async import command
  - cancellation token ownership and Cancel command
  - live `ProcessOutputLine` activity collection
  - Git readiness/status text
  - imported repository path and preserved backup path
  - reloads FBD-308 project header identity after success
- `MainWindow.xaml`
  - functional Repository Manager panel
  - Git URL / Branch / Workspace inputs
  - Import / Refresh and Cancel actions
  - indeterminate active-operation progress
  - live activity list
  - repository/backup result display
  - existing top Import Project button now invokes the real import command
  - existing FBD-308 project identity header remains intact

Production DI now registers the branch discovery/switch services that were previously implemented/tested but not composed into the application, plus the new resolver/coordinator/ViewModel.

## Safety properties

- An occupied non-Git target folder is never deleted or refreshed.
- Existing Git repositories use FBD-309 backup/staging/rollback instead of overwrite.
- Branch switching remains delegated to FBD-305 and therefore does not force-discard local changes.
- The UI does not mutate global PATH or environment variables.
- Git operations retain existing cancellation, timeout, progress and secret-redaction behavior.
- Successful safe refresh surfaces its backup location to the user.
