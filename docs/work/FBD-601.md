# FBD-601 — Locate Flutter project root

Status: DONE pending final-head CI and merge

## Goal

Locate the effective Flutter project root inside an imported repository without mutating repository contents and without taking over the YAML parsing responsibilities reserved for FBD-602.

## Implementation

- added `IFlutterProjectRootLocator` with typed success/failure states and candidate evidence
- performs bounded read-only traversal from the imported repository root
- skips generated/cache/VCS directories and reparse-point directories
- discovers `pubspec.yaml` candidates without parsing their contents
- validates Flutter root evidence using the local `.metadata` marker or `lib` plus at least one Flutter platform directory (`android`, `ios`, `web`, `windows`, `macos`, `linux`)
- prefers a valid repository-root Flutter project while retaining nested projects as evidence
- selects a single nested Flutter project only when unambiguous
- returns `Ambiguous` instead of guessing when a monorepo contains multiple nested Flutter projects
- if repository inspection is incomplete, does not promote a single nested candidate because uniqueness cannot be proven safely
- distinguishes invalid request, missing repository, missing pubspec, no Flutter filesystem evidence, ambiguity, traversal limits, and incomplete/failed inspection
- registered the locator in production DI

## Safety boundary

FBD-601 is filesystem inspection only. It does not run Flutter/Dart/Gradle, parse `pubspec.yaml`, change the repository, follow directory reparse points, or select arbitrarily between multiple app roots. Pubspec semantic parsing remains exclusively FBD-602.

A regression test explicitly places `sdk: flutter` text inside a pubspec with no Flutter filesystem markers and verifies that FBD-601 does not promote it. A second boundary test verifies `.metadata` evidence succeeds even when pubspec text is not valid YAML, proving that root discovery does not depend on YAML parsing.

Traversal is bounded to 4096 directories and 512 pubspec files; hitting either limit returns `InspectionFailed` instead of silently returning an incomplete project choice.
