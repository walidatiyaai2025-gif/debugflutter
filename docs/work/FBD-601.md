# FBD-601 — Locate Flutter project root

Status: IN PROGRESS

## Goal

Locate the effective Flutter project root inside an imported repository without mutating repository contents and without taking over the YAML parsing responsibilities reserved for FBD-602.

## Implementation

- added `IFlutterProjectRootLocator` with typed success/failure states and candidate evidence
- performs bounded read-only traversal from the imported repository root
- skips generated/cache/VCS directories and reparse-point directories
- discovers `pubspec.yaml` candidates and validates Flutter evidence using the local `.metadata` marker or the minimal `flutter: -> sdk: flutter` dependency shape
- prefers a valid repository-root Flutter project while retaining nested projects as evidence
- selects a single nested Flutter project when unambiguous
- returns `Ambiguous` instead of guessing when a monorepo contains multiple nested Flutter projects
- distinguishes missing repository, missing pubspec, non-Flutter pubspec, ambiguity, and incomplete/failed inspection
- registered the locator in production DI

## Safety boundary

FBD-601 is filesystem inspection only. It does not run Flutter/Dart/Gradle, parse package constraints, change the repository, follow directory reparse points, or select arbitrarily between multiple app roots.

## Coverage

Unit coverage includes repository-root selection, one nested app, ambiguous monorepos, missing pubspec, plain Dart pubspec, `.metadata` evidence, quoted `sdk: flutter`, generated-directory exclusion, and missing repository handling. Composition coverage verifies the production singleton registration.
