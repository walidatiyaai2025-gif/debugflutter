# FBD-307 — Detect dirty working tree

## Status

DONE

## Scope

Inspect a cloned Git working tree without mutating it so later repository operations can surface local changes instead of silently overwriting user work.

## Implementation

- Added typed working-tree scan contracts under `FlutterBuildDoctor.Git.Repository`.
- Added `GitWorkingTreeScanner` backed by the canonical `IProcessRunner`.
- Executes only `git status --porcelain=v1 -z --untracked-files=all`.
- Does not invoke `clean`, `reset`, `stash`, `checkout`, `switch`, or any other mutating Git command.
- Validates Git executable path, repository path, `.git` metadata, and timeout before scanning.
- Preserves cancellation and timeout behavior from the process engine.
- Keeps Git/GCM prompts non-interactive per process.
- Parses zero-terminated porcelain v1 records so spaces and special path characters are not split by shell-style parsing.
- Classifies modified, added, deleted, renamed, copied, type-changed, unmerged, untracked, and unknown states.
- Reports staged versus unstaged state for each change.
- Preserves rename/copy original paths.
- Preserves the raw porcelain payload and process receipt when parsing fails.
- Exposes explicit `IsClean` / `IsDirty` state only after a successful scan.
