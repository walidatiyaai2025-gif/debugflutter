# B150-091..100 — Devices & Emulators

Status: IN PROGRESS — implementation committed, CI validation pending

## Implemented scope

- B150-091: `adb devices -l` parser with raw evidence and property extraction.
- B150-092: explicit online/offline/unauthorized/recovery/bootloader/unknown state mapping.
- B150-093: physical/emulated device metadata projection and human-readable model names.
- B150-094: AVD list parser/model using `emulator -list-avds` output.
- B150-095: non-blocking detached emulator launch with typed `-avd` arguments.
- B150-096: cancellable, timed `adb -s <serial> wait-for-device` orchestration.
- B150-097: bounded `sys.boot_completed` polling with cancellation.
- B150-098: safe selected-emulator stop via `adb -s <serial> emu kill`.
- B150-099: APK install with explicit replace/downgrade policy flags.
- B150-100: cancellable logcat streaming with bounded retained output.

## Process-engine hardening

`ProcessRequest` now supports optional `MaxCapturedOutputLines`. `ProcessRunner` continues forwarding every live line through `IProgress<ProcessOutputLine>` while retaining only the configured tail in its final result. Existing calls keep unlimited capture when the option is absent.

A detached-process launcher was added so emulator launch does not block until the emulator exits.

## Safety

- All serial/AVD/path values are typed arguments, never shell-concatenated.
- Control characters are rejected from user-supplied identifiers/paths.
- APK install fails before execution when the requested file does not exist.
- Replace (`-r`) and downgrade (`-d`) behavior is explicit policy, not silently enabled.
- Boot waits and ADB readiness waits are bounded/cancellable.
- Logcat retained output is limited to 100-10,000 lines; default 2,000.

Release build and full tests must pass before the stacked PR is considered verified.
