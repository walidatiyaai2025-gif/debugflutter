# FBD-404 — Detect Flutter SDK + version

## Status

DONE

## Scope

Detect the effective Flutter SDK on Windows, expose the Flutter executable path, SDK root, framework version and channel, and preserve evidence when multiple Flutter installations are present on PATH.

## Integration design

FBD-404 composes the existing environment foundation instead of adding another PATH implementation:

- FBD-402 `IPathExecutableDiscovery` determines every `flutter` executable in effective Windows PATH/PATHEXT order.
- The first PATH match is the effective/preferred Flutter executable; later matches remain visible as shadowed conflict evidence.
- FBD-404 does not mutate PATH or any global environment variable.
- FBD-404 deliberately does not execute `flutter --version`; the structured command probe remains FBD-504.

## Flutter metadata source

The detector reads local SDK metadata from `bin/cache/flutter.version.json`, using the same cache file shape used by Flutter tooling (`frameworkVersion` and `channel`). A legacy fallback reads `<sdk>/version` plus `.git/HEAD` when the cache JSON is unavailable.

This keeps SDK discovery side-effect free: detecting Flutter does not warm up the SDK, download artifacts, start a Dart process, or alter the selected installation.

## Implementation

Added/expanded under `FlutterBuildDoctor.Flutter.Detection`:

- `FlutterSdkDetectionStatus`
- `FlutterVersionMetadataSource`
- `FlutterSdkDetectionRequest`
- `FlutterSdkCandidate`
- enriched `FlutterDetectionResult`
- `IFlutterSdkDetector`
- `FlutterSdkDetector`

The detector:

1. asks FBD-402 for all `flutter` PATH matches;
2. derives candidate SDK roots from the expected `<sdk>/bin/flutter.*` layout;
3. preserves preferred/shadowed/path-index metadata for every candidate;
4. selects only the effective PATH candidate for version/channel metadata;
5. reads `bin/cache/flutter.version.json` when present;
6. falls back to `<sdk>/version` + `.git/HEAD` for legacy SDK metadata;
7. returns explicit Missing / InvalidSdkLayout / MetadataMissing / MetadataInvalid / Cancelled states;
8. preserves malformed raw JSON evidence when parsing fails;
9. supports cancellation around filesystem reads;
10. exposes conflict status without silently picking a different SDK.

Production composition:

- the WPF app now references `FlutterBuildDoctor.Flutter`;
- `IFlutterSdkDetector` is registered as a singleton in runtime detection DI;
- no existing Git Repository Manager registration was changed or removed.
