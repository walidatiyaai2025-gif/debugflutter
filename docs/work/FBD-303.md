# FBD-303 — Clone repository

## Status

DONE

## Scope

Implement safe Git repository cloning on top of the existing process execution engine while preserving the URL validation and Git detection work already completed in FBD-301/FBD-302.

## Implementation

- Added typed clone request/result/status contracts in `FlutterBuildDoctor.Git.Cloning`.
- Added `GitCloneService` backed by the canonical `IProcessRunner`.
- Reuses `IGitRepositoryUrlValidator` from FBD-302 before any process starts.
- Supports a caller-selected target workspace and optional target folder name.
- Derives the target folder from the normalized repository URL when no folder name is supplied.
- Creates a missing workspace directory when it is safe to do so.
- Rejects unsafe target names, path traversal, target files, and non-empty target directories.
- Never deletes or overwrites existing repository/workspace content.
- Executes `git clone --progress -- <remote> <target>` so progress is emitted even when Git is not attached to a terminal.
- Streams the existing `ProcessOutputLine` progress channel directly to callers.
- Applies the existing process timeout/cancellation pipeline and maps cancelled/timed-out results explicitly.
- Sets `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=Never` per process to prevent hidden credential prompts from hanging the desktop application.
- Verifies `.git` metadata after a zero exit code before reporting clone success.
