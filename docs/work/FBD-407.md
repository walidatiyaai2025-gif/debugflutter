# FBD-407 — Detect Android SDK roots

Status: DONE pending final-head CI and merge

## Scope

Discover, normalize, validate, and prioritize Android SDK root candidates from the immutable FBD-403 environment snapshot without modifying process, user, or machine environment variables.

## Source precedence

For the current process, sources are evaluated in this order:

1. Process `ANDROID_SDK_ROOT`
2. Process `ANDROID_HOME`
3. User `ANDROID_SDK_ROOT` / `ANDROID_HOME` as persisted evidence
4. Machine `ANDROID_SDK_ROOT` / `ANDROID_HOME` as persisted evidence

Only Process-scope configuration is considered effective for commands launched by the current application. Persisted User/Machine values are retained as evidence and are not silently promoted.

Equivalent paths are deduplicated case-insensitively while preserving every source record.

## Validation

- trims surrounding whitespace and quotes
- requires a fully-qualified local path
- rejects unresolved `%VAR%` references rather than expanding hidden state
- rejects UNC/network roots from automatic probing
- verifies the directory exists
- recognizes Android SDK layout markers: `platform-tools`, `platforms`, `build-tools`, `cmdline-tools`, legacy `tools`, `licenses`, or `emulator`
- does not invoke `sdkmanager`, `adb`, or any SDK command

Detailed cmdline-tools/sdkmanager detection remains FBD-408. Detailed ADB/platform-tools detection remains FBD-409.

## Failure semantics

If the effective Process root is invalid while a different configured candidate is valid, detection reports the effective root as invalid and keeps the alternate as evidence. It does not silently choose the alternate and hide the environment conflict.

## Integration

- consumes `EnvironmentVariableSnapshot` from FBD-403
- `IAndroidSdkRootDetector` is registered as a singleton in production DI
- preserves FBD-402 PATH discovery, FBD-404 Flutter detection, and FBD-406 Java detection
- no environment mutation or external process execution

## Coverage

Unit tests cover:

- valid effective SDK root
- SDK_ROOT/HOME equivalent-root deduplication with both sources retained
- conflicting Process roots and SDK_ROOT precedence
- invalid effective root with valid alternate and no silent fallback
- User/Machine-only persisted roots
- missing roots
- existing directory without SDK markers
- UNC root rejection
- unresolved environment-variable reference rejection

Integration tests cover:

- production DI singleton resolution
- production FBD-403 environment snapshot consumption
- `ANDROID_SDK_ROOT` and `ANDROID_HOME` remain unchanged before/after detection
