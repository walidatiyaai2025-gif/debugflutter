# FBD-502 — Parse Flutter Doctor sections

Status: DONE pending final-head CI and merge

## Scope

Parse recognized sections from the raw `ProcessResult` produced by FBD-501. FBD-502 does not execute Flutter, mutate the environment, repair anything, or normalize raw output. Unknown-output modeling remains FBD-503.

## Implementation

- Added typed parser contracts:
  - `FlutterDoctorParseStatus`
  - `FlutterDoctorSectionKind`
  - `FlutterDoctorSectionStatus`
  - `FlutterDoctorSection`
  - `FlutterDoctorParseResult`
  - `IFlutterDoctorParser`
- Added `FlutterDoctorParser`.
- Recognized section kinds include Flutter, Windows Version, Android toolchain, Chrome, Visual Studio, Android Studio, VS Code, Connected device, Network resources, Xcode, and Linux toolchain.
- Maps doctor header markers to typed states:
  - `✓` → Ready
  - `!` → Warning
  - `✗` → Error
  - `-` → NotApplicable
  - any other marker → Unknown
- Every recognized section retains its exact source `ProcessOutputLine` records.
- The parse result retains the complete original `ProcessResult.Output` collection for downstream evidence/unknown-output handling.
- Any syntactically valid but unrecognized doctor header terminates the current recognized section, so unknown details cannot leak into the preceding recognized section.
- Parsing still runs when FBD-501 returned a failed process result if usable doctor evidence exists.
- Registered `IFlutterDoctorParser` in production runtime-detection DI.
