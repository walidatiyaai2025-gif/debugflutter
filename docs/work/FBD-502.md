# FBD-502 — Parse Flutter Doctor sections

Status: DONE pending final-head CI and merge

## Scope

Parse the raw `flutter doctor -v` process evidence produced by FBD-501 into typed section records. The parser consumes the existing `FlutterDoctorExecutionResult` / `ProcessResult`; it never reruns Flutter, performs no repair, and does not normalize or discard the original evidence.

## Implementation

- Added typed `FlutterDoctorParseStatus`, `FlutterDoctorSectionKind`, `FlutterDoctorSectionStatus`, `FlutterDoctorSection`, `FlutterDoctorParseResult`, and `IFlutterDoctorParser` contracts.
- Added pure `FlutterDoctorParser` with no subprocess or environment dependencies.
- Recognizes Flutter, Android toolchain, Android Studio, connected device, Windows Version, Chrome, Visual Studio, VS Code, and Network resources section titles.
- Recognizes current common Flutter Doctor health markers across Windows/non-Windows output: `✓` / `√` as passed, `!` as warning, and `X` / `x` / `✗` / `×` as failed.
- Section detection starts only from stdout header lines; stderr bracket text cannot create a false section.
- Every parsed section retains its exact original header `ProcessOutputLine` and exact original line objects, including any interleaved stderr details.
- Preamble or other lines before the first section are exposed as `UnsectionedLines` without modifying them.
- Unknown section headers are retained as `Unknown` sections so they cannot corrupt following recognized sections. FBD-503 remains responsible for the complete unknown-output preservation/representation policy.
- The original FBD-501 `FlutterDoctorExecutionResult` and `ProcessResult` remain directly available from the parse result.
- If process evidence is absent, the parser returns an explicit `NoProcessEvidence` state; if evidence exists but no valid headers are found, it returns `NoSections` while retaining all raw lines.
- Available section evidence is still parsed when the underlying doctor process finished with a failure status.
- Registered `IFlutterDoctorParser` in production runtime-detection DI.

## Coverage

Unit coverage verifies core Flutter/Android/Studio/device section parsing, additional known sections, Windows status glyphs, exact raw-line identity, stdout/stderr grouping, preamble handling, unknown-section isolation, malformed headers, absent process evidence, no-section evidence, and parsing available evidence from a failed execution.
