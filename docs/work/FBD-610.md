# FBD-610 — Parse versionName / versionCode

Status: IN PROGRESS

Issue: #110

## Goal

Represent the configured default Android release version from the exact FBD-604 app Gradle script and successful FBD-602 pubspec metadata without executing Gradle.

## Resolution rules

- inspect only direct `defaultConfig { ... }` declarations in the Android app build script
- support static Groovy/Kotlin `versionName` string literals and positive integer `versionCode` values
- recognize current Flutter references `flutter.versionName` / `flutter.versionCode`
- recognize legacy Flutter template references `flutterVersionName` / `flutterVersionCode.toInteger()`
- resolve recognized Flutter references from the parsed `pubspec.yaml` `version` field
- split the common `version: <build-name>+<build-number>` form into Android versionName and a positive 32-bit versionCode
- if the pubspec build number is missing or cannot be represented as a positive Android integer, leave versionCode unresolved rather than guessing
- preserve typed source evidence so consumers can distinguish explicit Gradle values from Flutter/pubspec-derived values
- repeated declarations are accepted only when they resolve to the same value; conflicting values are ambiguous
- any unresolved dynamic/non-literal declaration for a field prevents a static value for that same field from being treated as the effective configured value

## Scope boundary

- flavor/build-type version overrides are intentionally excluded; FBD-611 owns flavor analysis
- command-line `--build-name` / `--build-number` overrides are runtime build inputs and are not inferred by this static analyzer
- no Gradle/gradlew execution or Groovy/Kotlin expression evaluation
- no local.properties parsing in this task; FBD-613 owns local.properties analysis
- no project mutation and no raw Gradle source exposure through the result contract

## Safety

The parser revalidates the exact expected `android/app/build.gradle` or `build.gradle.kts` path supplied by FBD-604 and rejects stale, wrong-role, reparse/symlink, and scripts larger than 512 KiB before parsing.

## Coverage

Tests cover modern Kotlin/Groovy Flutter references, legacy Flutter variables, static values, parenthesized forms, source evidence, matching/conflicting duplicate declarations, missing/invalid pubspec build numbers, dynamic/interpolated/concatenated values, helper-variable false positives, conservative static+dynamic handling, flavor/build-type exclusion, comment/string lookalikes, missing FBD-602 evidence, wrong/stale paths, symlinks, oversized scripts, no-raw-source contract, and singleton DI composition.

## Validation

GitHub Actions on the feature branch and pull request is the authoritative build/test gate because the current local execution environment does not provide the .NET SDK.
