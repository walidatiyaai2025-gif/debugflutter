# FBD-412 — Detect emulator binary

Status: DONE pending final-head CI and merge

## Scope

Detect the Android emulator executable and version from the validated FBD-407 Android SDK root using a bounded read-only version probe. This task does not launch, stop, boot, or enumerate AVDs.

## Detection

- consumes the validated effective Android SDK root
- checks `<sdk>/emulator`
- locates `emulator.exe` with a portable `emulator` fallback
- reads emulator package `source.properties` and `Pkg.Revision`
- runs only `emulator -version` through the canonical `IProcessRunner`
- uses a 10-second timeout and preserves cancellation
- parses `Android emulator version ...` from stdout or stderr
- falls back to package revision when successful command output is not parseable
- preserves raw command output and raw package metadata
- reports command/package version mismatches without hiding either value

## Result states

- `Succeeded`
- `AndroidSdkRootUnavailable`
- `EmulatorDirectoryMissing`
- `EmulatorMissing`
- `ProbeFailed`
- `TimedOut`
- `Cancelled`
- `VersionUnavailable`

## Safety boundary

The only external argument emitted by this detector is `-version`. It never supplies `-avd`, launch/headless options, or any state-changing emulator operation.

## Integration

- `IAndroidEmulatorDetector` registered as a production singleton
- composes with FBD-407 root detection and canonical process execution
- keeps source metadata available when process probing fails or times out

## Coverage

Unit tests cover command-version parsing, metadata fallback, command/package mismatch, missing package directory, missing executable, timeout, process failure, no-version evidence, and pre-cancellation.

Integration coverage validates FBD-407 -> FBD-412 composition with a deterministic process runner and asserts the exact single `-version` argument with no AVD launch arguments.
