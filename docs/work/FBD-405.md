# FBD-405 — Detect Dart SDK + version

Status: DONE

## Scope

Detect Dart SDK executable/version evidence and explicitly link Flutter-bundled Dart to the effective Flutter SDK while preserving standalone/PATH conflicts. Detection is local/read-only and does not execute or update Dart/Flutter.

## Discovery

- consumes FBD-402 `IPathExecutableDiscovery` for every PATH `dart` match
- consumes FBD-404 Flutter SDK evidence
- detects Flutter-bundled Dart under `<flutter>/bin/cache/dart-sdk/bin`
- links bundled Dart whenever Flutter is installed and its SDK path is known, even if Flutter version metadata is incomplete
- reads Dart version from `<dart-sdk>/version`
- derives each Dart SDK root from its executable `bin` directory
- preserves raw version metadata

## Conflict semantics

- PATH preferred/shadowed evidence remains visible
- bundled Dart and PATH Dart are deduplicated when they are the same executable
- `HasFlutterPathMismatch` is explicit when PATH-preferred Dart differs from Flutter-bundled Dart
- standalone Dart is never silently promoted over bundled Flutter Dart or vice versa
- no PATH/environment changes occur

## Result states

- `Succeeded`
- `Missing`
- `MetadataMissing`
- `MetadataInvalid`
- `Cancelled`

## Integration

- `IDartSdkDetector` registered as a production singleton
- uses FBD-402 PATH discovery and FBD-404 Flutter evidence
- no external process execution

## Coverage

Unit tests cover bundled Dart also preferred on PATH, standalone-vs-bundled mismatch, multiple PATH candidates/shadowing, bundled Dart absent from PATH, incomplete Flutter metadata with usable bundled Dart, standalone-only Dart, no Dart, missing/empty Dart version metadata, and pre-cancellation.

Integration coverage validates real `WindowsPathExecutableDiscovery` against a temporary Flutter-bundled Dart SDK and confirms the candidate is simultaneously linked to Flutter and PATH-preferred without environment mutation.
