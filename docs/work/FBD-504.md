# FBD-504 — Run flutter --version structured probe

Status: DONE

## Scope

Run only the already-detected Flutter executable with `--version`, capture the complete process evidence, and project version metadata into a typed result. No Flutter update, PATH/environment mutation, doctor execution, repair, or UI behavior is introduced.

## Implementation

- Added `IFlutterVersionProbe`, `FlutterVersionProbeRequest`, `FlutterVersionProbeResult`, and `FlutterVersionProbeStatus`.
- Reuses FBD-404 `FlutterDetectionResult` and canonical `IProcessRunner`.
- Uses a bounded one-minute default timeout and preserves cancellation.
- Windows `.bat` / `.cmd` Flutter executables run through `cmd.exe /d /v:off /c <flutter> --version`; direct executables run directly.
- Preserves the complete raw `ProcessResult` for success, failure, timeout, cancellation, and parse failure.
- Parses stdout only; stderr cannot populate structured version fields.
- Structured fields include Flutter version, channel, repository URL, framework revision/date, engine hash/revision/date, Dart version, and DevTools version.
- Required success fields are Flutter version, channel, framework revision, and Dart version. Missing required fields return `ParseFailed` with partial fields and raw evidence preserved.
- Registered `IFlutterVersionProbe` in production runtime-detection DI.

## Windows encoding regression fixes

Real Windows command-shim integration exposed multiple console/code-page representations of Flutter's bullet separator:

- U+2022 `•`
- ASCII BEL (`U+0007`)
- OEM mojibake `ΓÇó`
- Windows-1252 mojibake `â€¢`

The parser normalizes only a temporary parse copy of these known separator aliases. `ProcessResult.Output` remains exact raw text evidence from the process runner.
