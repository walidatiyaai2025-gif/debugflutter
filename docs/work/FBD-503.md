# FBD-503 — Preserve unknown Flutter Doctor output

Status: DONE pending final-head CI and merge

## Scope

Extend the FBD-502 Flutter Doctor parser so output that is new, malformed, or outside recognized sections is represented explicitly rather than disappearing. Preserve exact original `ProcessOutputLine` objects and ordering. Do not rerun Flutter, repair the environment, trim evidence, or add UI behavior.

## Implementation

- Added `FlutterDoctorUnknownEvidenceKind` with:
  - `UnknownSection`
  - `MalformedSectionHeader`
  - `UnclassifiedLine`
- Added `FlutterDoctorUnknownEvidence` containing kind, original output start index, exact original line objects, and a parser reason.
- Extended `FlutterDoctorParseResult` with ordered `UnknownEvidence` and `HasUnknownEvidence`.
- Unknown section headers already recognized structurally by FBD-502 are now surfaced as one ordered `UnknownSection` evidence block while remaining present in the normal section list.
- Section-like stdout lines that cannot form a valid header are surfaced as `MalformedSectionHeader` evidence.
- Malformed header-like lines encountered inside a known section remain inside that section's exact line context while also being exposed as malformed evidence; the parser does not invent a section split.
- Preamble, stderr before the first section, and other unclassified lines are surfaced as `UnclassifiedLine` evidence.
- Unknown evidence is sorted by the original `ProcessResult.Output` index so diagnostics preserve source order.
- `NoSections` retains all original unsectioned lines and explicitly classifies their unknown evidence.
- `NoProcessEvidence` does not invent evidence.
- Known-section parsing behavior from FBD-502 remains unchanged.

## Coverage

Regression coverage verifies:

- unknown section blocks retain exact header/detail object identities;
- trailing whitespace in unknown detail text remains unchanged;
- malformed section-like lines before and inside known sections are represented explicitly;
- malformed lines inside a known section remain in that section's line context;
- unknown evidence is returned in original source order;
- known-only output produces no unknown evidence;
- no-section output classifies every preserved unsectioned line;
- missing process evidence produces no invented unknown evidence;
- the original `ProcessResult` remains available unchanged.
