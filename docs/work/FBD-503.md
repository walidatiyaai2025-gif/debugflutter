# FBD-503 — Preserve unknown doctor output

Status: DONE

## Scope

Extend the FBD-502 Flutter Doctor parser so future/unknown output is explicitly represented without rerunning Flutter, repairing the environment, normalizing text, or changing existing known-section membership.

## Implementation

- Added `FlutterDoctorUnknownEvidenceKind` with:
  - `UnknownSection`
  - `MalformedSectionHeader`
  - `UnclassifiedLine`
- Added `FlutterDoctorUnknownEvidence` containing the original output start index, exact original `ProcessOutputLine` references, and a diagnostic reason.
- Extended `FlutterDoctorParseResult` with:
  - `UnknownEvidence`
  - `UnknownSections`
  - `HasUnknownEvidence`
- Unknown syntactically valid doctor headers remain normal `FlutterDoctorSectionKind.Unknown` sections and are also exposed explicitly as `UnknownSection` evidence.
- Malformed header-like stdout lines are explicitly surfaced as `MalformedSectionHeader` evidence.
- stderr lines are explicitly surfaced as `UnclassifiedLine` evidence and are never interpreted as section headers.
- Preamble/unsectioned stdout lines are surfaced as `UnclassifiedLine` evidence.
- Existing FBD-502 section membership is intentionally preserved. Contextual lines can remain attached to their section while the exact same raw object is also exposed as unknown evidence.
- `StartIndex` records the position in the original `ProcessResult.Output` sequence so consumers can reconstruct evidence ordering without changing text.

## Safety / Evidence Rules

- No external process execution.
- No environment or project mutation.
- No repair behavior.
- No text normalization or synthetic replacement of raw output.
- Original `FlutterDoctorExecutionResult`, `ProcessResult`, and `ProcessOutputLine` objects remain available.
- Known FBD-502 section parsing semantics remain unchanged.

## Coverage

Unit regressions verify:
- unknown sections are retained and exposed as explicit unknown evidence
- exact source object identity and source indexes
- stderr before and inside known sections
- malformed header-like lines inside and outside sections
- unsectioned/preamble output
- failed doctor executions with usable evidence
- no-process-evidence behavior
- existing known section membership remains unchanged
