# FBD-503 — Preserve unknown doctor output

Status: DONE pending final-head CI and merge

## Scope

Extend the FBD-502 Flutter Doctor parser result so future or malformed Flutter Doctor output is represented explicitly without rerunning Flutter, changing known-section classification, repairing the environment, or discarding raw process evidence.

## Integration approach

- Preserved the existing FBD-503 team implementation rather than redesigning it.
- The original FBD-503 branch had diverged from `agent/fbd-foundation` and contained stale experimental history created before later integration cleanup.
- Transplanted only the three FBD-503 feature files onto clean branch `agent/fbd-503-preserve-unknown-output-clean` created from integration head `18a65a65f43aa03bd2986a381957a9c9ca69a4fe`.
- No force-push, history rewrite, or reintroduction of the stale placeholder commits was used.

## Implementation

- Added `FlutterDoctorUnknownEvidenceKind` with explicit categories:
  - `UnknownSection`
  - `MalformedSectionHeader`
  - `UnclassifiedLine`
- Added `FlutterDoctorUnknownEvidence` containing:
  - evidence kind
  - original output `StartIndex`
  - exact original `ProcessOutputLine` objects
  - a human-readable preservation reason
- Extended `FlutterDoctorParseResult` with `UnknownEvidence` and `HasUnknownEvidence` while retaining the existing `Sections`, `UnsectionedLines`, `Execution`, and `ProcessResult` evidence.
- Unknown section groups are preserved as one ordered evidence record containing their exact header/detail line objects.
- Section-like stdout lines that cannot be parsed are preserved as `MalformedSectionHeader` evidence.
- Preamble, stderr-before-section, and other output that is not classified into a section is preserved as `UnclassifiedLine` evidence.
- Evidence is sorted by the original `ProcessResult.Output` index so its relative order remains deterministic.
- Malformed lines encountered inside a recognized section remain in that section's original `Lines` collection and are additionally exposed as malformed evidence; known-section parsing therefore remains unchanged.
- No subprocess is started by FBD-503 and `flutter doctor -v` is never rerun.

## Coverage

Added `FlutterDoctorUnknownEvidenceTests` covering:

- unknown/preamble/malformed evidence in original output order
- exact `ProcessOutputLine` identity and verbatim text preservation
- known-only output producing no unknown evidence
- no-section output classifying every preserved raw line
- no-process-evidence behavior without inventing unknown records
- continued preservation of malformed lines inside recognized section evidence

Existing FBD-502 parser tests remain unchanged.
