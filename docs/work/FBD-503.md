# FBD-503 — Preserve unknown doctor output

Status: DONE pending final-head CI and merge

## Scope

Extend the merged FBD-502 Flutter Doctor parser so unknown and malformed output is represented explicitly instead of disappearing. The parser continues to consume the existing FBD-501 `FlutterDoctorExecutionResult.ProcessResult`; it does not rerun Flutter, repair the environment, or normalize raw evidence.

## Implementation

- Added `FlutterDoctorUnknownEvidenceKind` with:
  - `UnknownSection`
  - `MalformedSectionHeader`
  - `UnclassifiedLine`
- Added `FlutterDoctorUnknownEvidence` carrying the original output index, original `ProcessOutputLine` objects, and an explanatory reason.
- Extended `FlutterDoctorParseResult` with `UnknownEvidence` and `HasUnknownEvidence` while retaining the original execution/process result.
- Unknown typed doctor sections are also exposed as grouped unknown evidence with all original section lines.
- Preamble/unsectioned lines are exposed individually as unclassified evidence.
- Header-like stdout lines that cannot be parsed are exposed as malformed-section evidence.
- Non-stdout lines encountered inside recognized sections are explicitly exposed as unclassified evidence while remaining in the original known section line collection, preserving FBD-502 semantics.
- Evidence is ordered by original process-output index.
- No output text is trimmed, rewritten, or discarded from the source evidence.

## Coverage

Unit tests cover:
- preamble/unclassified output
- malformed section headers before and inside known sections
- grouped unknown section headers/details
- exact raw text preservation, including trailing spaces
- original evidence ordering
- known-only output producing no unknown evidence
- stderr with no sections
- stderr inside a known section being explicit unknown evidence without changing the known section's original lines
- no-process-evidence behavior without invented evidence
