## Confirmed starting point

The foundation already contained a valid Generic Host bootstrap in `App.xaml.cs`, plus `CommunityToolkit.Mvvm` and `Microsoft.Extensions.Hosting` package references. `MainWindow` was resolved from DI, but it had no injected ViewModel/DataContext and there was no presentation composition root.

## Implementation

- Added `MainWindowViewModel` based on `CommunityToolkit.Mvvm.ComponentModel.ObservableObject`.
- Added `AddFlutterBuildDoctorPresentation()` as the presentation composition root.
- Registered `MainWindowViewModel` and `MainWindow` as singletons.
- Changed `MainWindow` to require `MainWindowViewModel` through constructor injection and assign it to `DataContext`.
- Kept the existing Generic Host startup/shutdown lifecycle and switched startup registration to the composition-root extension.
- Added a Windows integration test that verifies the shell ViewModel resolves and the MainWindow registration exists without constructing WPF UI on a non-STA test thread.
