# B150-071..080 — Flutter Command Center core

Status: IN PROGRESS — implementation committed, CI validation pending

## Implemented scope

- B150-071: typed Flutter command builder; no shell command concatenation.
- B150-072: `flutter pub get` execution service.
- B150-073: `flutter clean` execution service.
- B150-074: `flutter analyze` execution with info/warning/error summary.
- B150-075: `flutter test` execution with explicit pass/cancel status.
- B150-076: `flutter pub outdated` execution.
- B150-077: `flutter devices --machine` execution.
- B150-078: `flutter emulators` execution.
- B150-079: typed `flutter run -d` request with optional flavor and Dart target.
- B150-080: progress and cancellation are forwarded through every command to the shared process engine.

## Safety and behavior

- User-provided executable/path/device/flavor/target values reject control characters.
- Device, flavor and target are individual `ProcessRequest.Arguments`; they are never concatenated into a shell command string.
- Finite inspection/build-prep commands have bounded timeouts.
- `flutter run` intentionally has no forced wall-clock timeout because it is a long-lived interactive process; explicit cancellation remains available.
- Command results retain the shared `ProcessResult`, including sanitized command, output, exit status, duration and execution receipt when available.

## Validation gate

Release build and full test suite must pass before the stacked PR is considered verified.
